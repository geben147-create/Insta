# 개선 방법 5가지 — 새 A/B 실험 전 추천 순위

가장 먼저 시험할 방식은 ‘자막 7편 전문을 한 번 읽힌 뒤, 이번 구간과 같은 역할의 예문을 골라 단계별로 집필하고, 낭독 본문만 따로 검수하는 방식’입니다. 저장소 이름보다 실제로 입력된 예문과 검수 경계가 중요합니다. 이는 사용자 경험과 문서 근거에 따른 설계 추천이며, 이 대본으로 새 A/B 실험을 한 결과는 아닙니다.

|순위|방법|장점|단점·주의|
|---|---|---|---|
|1|7편 전문 읽기 + 구간별 예문 + 순차 집필 + 낭독 전용 검수|사용자가 좋다고 느낀 훅 제작 방식을 본문에도 적용. 전체 맥락을 유지하면서 각 구간의 말투와 연결을 직접 제어.|구간마다 앞부분을 다시 설명하거나 반전을 중복할 수 있어 연결표가 필요. 단계가 많아 호출·검수 시간이 늘어남.|
|2|7편 전문 + 전체 대본 한 번 집필 + 별도 교정|지금 사용자가 만족했던 직접 입력 방식과 가깝고, 전체 흐름과 인물·사건 연결을 한 번에 볼 수 있음.|중간 문단의 문체가 흐트러지거나 연출 설명이 섞여도 집필 도중 발견하기 어려움. 전문 7편의 길이에 따라 입력 한도 확인 필요.|
|3|옵시디언의 대본 전용 예문을 명시적으로 읽힌 뒤 단계별 집필|승인된 예문과 수정 이력을 재사용하기 쉬움. 어떤 파일의 어느 문장을 읽혔는지 기록 가능.|파일을 저장하기만 하고 실제 집필 입력에 넣지 않으면 효과를 보장하지 못함. 와디즈·홈페이지 카피 규칙이 섞이면 대본 리듬을 해칠 수 있음.|
|4|공통기억의 요약 규칙 + 금지 문장 목록|빠르고 일관된 기본 규칙·말투·제외 주제를 공유하기 좋음.|‘자연스럽게 써라’는 규칙만으로 실제 문장 리듬을 충분히 보여주기 어려움. 긴 작업 중 규칙 적용 여부를 별도로 확인해야 함.|
|5|GBrain·Graphify 등 검색·관계 그래프에서 예문 회수|참고자료가 아주 많을 때 관련 문서·인물·근거를 찾는 데 활용 가능.|검색·관계 연결 기능만으로 낭독 문장의 품질 향상을 보장할 수 없음. 검색 결과가 대본 예문이 아닌 설명 문서면 같은 문제가 남음. 현재 사용자 환경에서 두 제품의 대본 품질 비교 실험은 하지 않음.|

## 크론과 순차 실행
크론잡과 순차 실행은 다른 축입니다. 크론잡은 ‘언제 시작할지’, 순차 제어는 ‘어떤 단계가 완료·검수되어야 다음으로 갈지’를 정합니다. 지금 즉시 시작해도 순차 제어를 쓸 수 있고, 같은 제어를 나중에 크론으로 시작할 수도 있습니다.
단계별 작업을 10분 간격처럼 시각만 달리 예약하는 방식은 권하지 않습니다. 앞 단계가 끝났는지·검수됐는지·같은 run_id인지 확인하는 성공 게이트가 필요합니다. Hermes의 context_from은 이전 결과를 넘기는 기능이지, 사용자 승인이나 이번 실행의 품질 통과를 증명하는 기능이 아닙니다.
