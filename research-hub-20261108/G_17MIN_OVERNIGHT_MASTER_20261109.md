## 10. 영상 편집 에이전트 실행 프롬프트 (기존 FFmpeg/H3/TTS, GPU 충돌 금지)

'원본 화면 70%면 저작권 면책'은 금지. 표시되는 2~3초 컷의 권리·맥락도 별도로 확인한다.
번역 SRT는 외국어 원음 IN/OUT 타임코드와 함께, TTS 자막은 말의 정확한 시각과 맞춘다. 한국어 자막은 크고 읽기 쉬우며 중요 인물 얼굴을 가리지 않는다.

## 11. 밤샘 병렬·중단 복구 구조: 가장 중요한 부분

1) 하나의 MASTER만 작업 리스트와 최종 결과 폴더를 쓴다. 2개의 마스터를 실행해 같은 프로젝트 파일을 동시에 덮어쓰지 않는다.
2) 작업 ID는 고정: KR17_20261109_01. 각 시도는 attempt N, 결과는 immutable file+SHA256, 상태는 별도 JSON. 중복 아이디로 새로운 작업 재등록 금지.
3) 새 디렉토리:
   jobs/KR17_20261109_01/{input,source_index,rights,news,script,tts,visuals,clips,video_chunks,subtitles,audio,preview,final,qc,logs,checkpoint}
   실제 전체 절대경로는 SSD PROJECT_ROOT 확인 후 지정.
4) state.json과 work_queue.jsonl 및 worker_heartbeat.json를 생성하고 상태는 DISCOVERED → VERIFIED → SCRIPTED → RIGHTS_CHECKED → AUDIO_READY → CLIPS_READY → PREVIEW_QC_PASS → CHUNKS_READY → FINAL_QC_PASS → GENERATED. 실패 시 FAILED_RETRYABLE, 권리 부족 BLOCKED_FOR_RIGHTS, CAPTIONS_MISSING, BLOCKED_FOR_USER로 정확히 기록.
5) 상태 전환은 임시 .tmp 기록→fsync/원자적 rename, 각 파일 완료 후 SHA256 및 ffprobe로 확인. 작업자 재시작 시 GENERATED 결과의 해시를 검증하고 해당 단계 SKIP. 동일 출력 경로를 여러 작업자가 쓰지 않도록 lock(예: flock) 하나 사용.
6) 워커 수 권장 상한: ego 브라우저 1(로그인·탭 충돌 방지), 조사/근거 정렬 최대2, 스크립트 최대1, TTS 최대1, 비디오 렌더1, 합성/자막 QC1. 무조건 10개·100개 병렬 금지. 두 RTX3090의 현재 작업과 VRAM이 허락한 경우에만 자원별 분리.
7) 한 작업 실패 시 분류:
   - URL/403/429/로그인/자막 없음: 그 소스를 블록하고 다음 후보 탐색(차단 우회 금지)
   - 클라우드 429/한도: 지수형 간격 대기 후 제한된 2회 재시도, 다음 작업은 로컬에서 계속
   - 모델/TTS/FFmpeg 일시 오류: 실패 청크만 최대2회, 그다음 BLOCKED_REVIEW
   - GPU OOM: 다른 모델을 종료하지 않고 해당 생성 단계 즉시 보류. 가능하면 더 작은 배치로 1회만 시도(현재 서비스 영향 없을 때)
   - 저작권/원음 미확인: 자동 우회 금지, 대체 허가 자산을 찾거나 미완성으로 보고
8) 기존 Hermes gateway cron에서 **1회 작업 시작 및 진행 상황 검증**을 맡길 수 있다. cron을 무한정 중첩 생성하지 않는다. 만료 이후 고아 작업 방지; 기존 job ID를 list에서 확인하고 같은 스케줄을 중복 생성하지 말 것.
9) 실제 장시간 실행 프로세스는 설치된 systemd user service 또는 tmux 분리 세션을 사용한다. 자식 프로세스와 로그·상태를 새 프로젝트 경로로 제한. 일반 대화창 닫힘을 신호로 종료하지 않게 설계. supervisor 실행 전에 STOP 조건과 승인범위 검증.
10) 체크포인트/하트비트: 60초마다 worker heartbeat 갱신(프로세스 자체 또는 기존 scheduler), 5분 진행/단계 변동 없으면 HANGING 기록하고 해당 청크만 제한 재시도. Gateway cron tick만으로 장시간 실행 자체의 생존을 가정하지 말 것.
11) 경합이 있으면 작업자 축소→원본 보존→안전한 분석 진행. 작업자가 여러 프로세스를 kill하거나 운영 서버를 건드리는 행동 금지.
12) Cloud Claude가 Hermes에서 이미 선택돼 있으면 기존 경로 그대로 사용. 추가 Claude Desktop/CLI를 동시에 새로 열어 동일 API 잔여 예산을 경쟁시키지 않는다. provider·계정·quota는 실제 실행환경에서 확인.
13) 06:40 이후 유료 모델 호출 시작하지 않고 남은 안전한 로컬 검수·패키징에 집중. 마감이면 파일 상태를 완료/부분완료/권리미확보로 분리.
14) 큰 17분 본편 1개 완료 전에는 100개 영상을 무리하게 렌더하지 않는다. 대신 원본 확보·권리 통과한 후속 TOP10 기획과 2~3개 독립 초고를 병렬 산출할 수 있음.
15) 모든 자동화 스크립트는 실제 로컬 Hermes/Claude가 현재 명령 및 시스템 설치 여부를 점검한 뒤 작성·실행한다. 이 문서만으로 아무 프로세스도 자동 기동되지 않는다.
