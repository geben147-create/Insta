A. 최초 1회 — 원문·규칙 등록
새 세션·새 프로젝트에서 원문과 명세를 처음 정리할 때

[A · 최초 1회 / 사용자 원문과 실행 규칙 등록]

지금 작업은 기존 국뽕 영상 제작 체계에 내가 준 디자인·편집 요구를 정확히 등록하는 것이다. 원문을 요약한 문서만 읽고 임의 구현하지 말고, 내가 첨부한 실제 대화·디자인 명세·참고 이미지와 기존 프로젝트를 먼저 대조한다. 이 프롬프트는 새 프로젝트나 새 편집기를 만들라는 지시가 아니다.

1. 원문과 정규화 규칙을 분리한다.
- 내가 제공한 원문 파일은 토씨·색 코드·부호·개행을 수정하지 않고 그대로 보존한다. 사용자 발화, 내가 붙인 JSON/명세, Claude 자신의 실행 보고가 섞여 있으므로 각각 출처 유형을 붙인다.
- 원문을 지우거나 간추린 글로 바꾸지 않는다. 실행에 필요한 정규화 표는 별도 파일로 추가하고 원문 위치를 연결한다.
- 구분은 ①사용자 확정 ②참고 이미지 실측 ③Claude 보고 ④🌸추가 제안으로 고정한다. 직접 확인한 구현 사실은 별도 검증란에 쓴다. Claude가 “했다”고 쓴 내용은 실제 파일·코드·프레임을 확인하기 전까지 완료로 쓰지 않는다.
- 우선순위는 최신 사용자 직접 요청, 이전 사용자 직접 요청·제공 명세, Claude 요약 순이다. 이전 ChatGPT의 범용 팔레트·다큐 비율·추천 폰트가 사용자 지정값을 덮지 못한다. 최신 요청으로 해결되는 충돌을 다시 질문하며 기다리지 않는다. 확인 불가 항목만 미확인으로 남기고 가능한 교정은 진행한다.

2. 확정 디자인을 역할별로 기록한다.
- 기본 키워드: 레코체, 흰 글씨 #FFFFFF, 검정 외곽선 #111111, 핵심어 하나의 뒤쪽에 형광 표시. 오래된 keyword JSON의 acc=#e60f2f는 노랑/연두/하늘 형광 지시와 충돌하므로 범용 빨강으로 사용하지 않는다. “편당 형광1색”은 원문에 없는 단위다.
- 사용자가 제공한 기존 팔레트: 연연두 배경 #F5FFDC, 형광 연두 #D9FF65, 연분홍 #FEE9F2, 주의 박스 #FCF1ED. 각 용도를 유지한다.
- 최신 언론 참고 캡처의 대표 실측값: 왼쪽 연두 #C7F001, 오른쪽 연노랑 #F2F586. 축소·압축된 캡처에서 추출한 대표값이며 방송 원본의 제작 HEX를 확정한 것은 아니다. 이 값은 기존 #D9FF65와 별도로 기록한다. 이번 기사형 형광색 교정에서는 최신 참고 캡처 대표값을 사용한다.
- VS 글자만 #E21317. 이전 #FFD54F, #B71512는 적용하지 않는다. 좌우 카드는 흑백 반투명으로 뒤 영상이 보이게 한다. 규칙에 없는 빨간 알약 태그는 넣지 않는다.
- 풀파티 예시 스타일: 티몬 몬소리 Black, 흰 글씨 #FDFDFC, 핵심 명사 #E03C3E, 양끝 번개 #D94B50. 외곽선0·그림자0, 작은 첫 줄55%, 자간-1px, 줄/글자 기울기0°, 세로100%, 배경 투명. 38px는 기존 시안의 기준 캔버스·배율을 먼저 확인한다.
- 재능이 없는 예시 스타일: 티몬 몬소리 Black, 흰 본문 #FDFDFD, 강조어 위 #E25254→아래 #F26163, 외곽선 #111114·5px, 그림자 #111114·2px, 라벨 배경 #040506·글씨 #EFEFEF, 줄-1.5°, 세로116%, 자간-1.5px, 배경 투명. 38px 역시 기존 기준 배율을 확인한다.
- 한마디 평가: 정선아리랑뿌리체 계열, 먹색 #040404·흰 외곽선 #FBFAF8, 마지막 낱말 #FCFCFC·검정 외곽선 #080404, 검정 그림자. 작은 머리말+큰 본문 구조를 유지한다. 첫 줄45%, 외곽선6px, 그림자4.5px·번짐0. 56px의 기준 배율도 확인한다.
- 댓글: Do Hyeon, 본문 #111111, 강조 #73F282. 실제 원문·번역·좋아요를 구분하고, 카드1개+내 캐릭터1개를 중심으로 한다. 예시 문구·닉네임·좋아요 수를 실제 반응으로 재사용하지 않는다.
- 그런데 반전: 해당 장면만 의도적 정지·흑백·짧은 흔들림, 편당2~3회라는 원문을 보존한다. 일반 컷까지 멈추게 만들지 않는다.
- 금빛 색·별34개·금가루200개, 11종 강제 혼합·같은 종류 연속 금지는 현재 첨부에서 사용자 직접 근거가 확인되지 않는다. 기존 자산은 보존하되 Claude 보고 항목으로 분리한다.

3. 공통 표현과 보호 조건을 정리한다.
- 기본 자막과 디자인 자막은 동시 표시하지 않는다. 한마디 평가의 작은 머리말+큰 본문은 하나의 디자인이며 이 2줄 구조를 금지하지 않는다.
- 언론과 댓글은 별도 의미 유형이다. 타이핑 효과는 공유할 수 있지만 기사 헤드라인 띠를 댓글의 기본 레이아웃으로 사용하지 않는다.
- 배경 영상은 보이게 유지한다. 흰 글씨의 검정 반투명 배경과 검정 글씨의 흰 배경은 후속 사용자 명세에 있으므로 “통계에서만 어둡게”라는 Claude 요약으로 삭제하지 않는다.
- 자막 하단 배치, 상단 임의 소제목·로고 금지, 카드/VS/그래프의 위·가운데 허용은 현재 제공된 요약에서 확인된 기존 보호 조건으로 유지한다. 사용자 직접 원문 근거가 확인됐다고 표시하지는 않는다.
- 이후 지시대로 해외 원문·중국어·일본어 글씨를 보존하고, 제거가 필요한 하단 원본 자막·로고만 정확한 영역으로 처리한다. 자연스러운 블러 지시를 적용하고 모든 글자를 일괄 감지해 지우지 않는다.
- 이미 생성된 대본·TTS는 고정이다. 내레이션60% 규칙은 삭제됐고 약90%는 현황이지 새 목표가 아니다. 컷4초 이하 조건은 유지하면서 화면·음성의 연속성을 검사한다.
- 기존 HumanTouch와 디자인 코드를 재사용한다. 생성 자산6장은 실제 파일·투명도·미리보기를 확인하고 VS/NO/가장자리/아래 불벽/인물 뒤 아우라/번개에 각각 연결한다.

4. 🌸실행 구조 제안
🌸스타일별 색·폰트·효과·줄바꿈을 한 원천에 등록하고 시안과 렌더러가 같은 값을 읽게 한다. 스타일마다 임의 색을 다시 작성하는 중복 코드를 없앤다.
🌸각 장면에 semantic_type, style_id, primary_caption, 원문 근거, 자료 출처, 적용/미적용 이유를 기록한다. 필드 이름은 기존 구조와 맞춰도 되지만 역할을 합치지 않는다.
🌸실제 로딩 폰트·최종 색·자막 레이어 상태를 렌더 manifest에 기록한다. 미해결 폰트를 조용히 다른 글꼴로 대체해 완료 처리하지 않는다.

5. 저장·보고
기존 파일을 덮기 전 변경 전후를 복구할 수 있게 보존한다. 규칙표·원문 출처·적용 상태를 같은 마스터 번호로 연결한다. 이 단계 결과는 등록/확인/미확인으로 보고하고 실제 MP4가 수정됐다고 쓰지 않는다. 새 제안에는 항상 🌸를 붙인다. 💰🌸허가받은 영상의 맥락을 보존하는 편집을 우선하고, 반전·크롭·배속만으로 권리나 수익화가 보장된다고 쓰지 않는다.

- 렌더 시작 전에 폰트 준비 완료를 기다리고, 시안과 최종 렌더가 동일한 폰트를 쓰는지 결과 이미지로 확인한다. 준비 안 된 폰트를 사용됐다고 보고하지 않는다.
- 재배포 권리를 확인하지 않은 폰트 파일을 GitHub에 추가하지 않는다. 로컬 설치 폰트나 허용된 공식 배포 경로를 사용한다.
🌸색·폰트·스타일을 공유 원천에서 읽게 하고, renderer가 비슷한 색을 따로 하드코딩하지 못하게 한다. 글자와 도형 오버레이의 색을 바꾸는 전역 opacity/filter/블렌딩도 확인한다.

[3. 자막 중복과 문맥 선택]
- 기본 자막과 디자인 자막의 동시 노출 금지는 이미 내가 준 요구다. 평가·번개·라벨·금빛 등 주 디자인 자막이 켜진 시간에는 별도 기본 하단 자막을 끈다. 평가의 작은 머리말+큰 본문은 하나의 디자인이므로 유지한다.
🌸primary_caption을 한 상태로 선택하도록 한다. 숨긴 기본 자막의 빈 상자·배경까지 남지 않도록 한다. 디자인 종료 후 필요한 기본 자막은 원래 타임코드로 복귀한다. 숨김 때문에 말의 정보가 없어지지 않게 그 구간의 디자인 자막에 기존 대사 그대로 담거나 디자인의 표시 구간을 줄인다. 대본 문구를 새로 쓰지 않는다.
- 언론 semantic_type과 댓글 semantic_type을 분리한다. 타이핑만 공유하고 출처 유형·카드형태는 섞지 않는다. 언론은 실제 기사 헤드라인·출처·참고 형광색, 댓글은 카드1개+내 캐릭터1개와 원문·번역·좋아요가 중심이다.
- 댓글 앱형/말풍선형/카드형 3종을 기존 기능으로 비교할 수 있게 하고 기사 띠를 댓글의 기본 스타일로 고정하지 않는다.
- 최신 V7 명세대로 해외 원문·중국어·일본어 글씨를 보존한다. 제거가 필요한 원본 하단 자막·로고만 정확한 영역에서 자연스러운 블러로 처리하고, 모든 글자를 OCR로 일괄 감지해 지우지 않는다. 이전 모자이크·전체글자 블러 지시로 되돌리지 않는다.
- 기존 보호 조건인 하단 자막 배치, 상단 임의 소제목·문장·로고 금지를 유지한다. 언론/댓글카드/VS/그래프는 기존 허용 영역을 사용한다. 이 조건은 제공된 Claude 요약에서 온 것으로 기록하고, 새로운 사용자 직접 인용으로 꾸미지 않는다.
- 글자·낱말 하나가 외롭게 떨어지지 않게 의미 단위로 줄바꿈하고 박스의 글씨 정렬을 확인한다. 기존 대본의 내용은 수정하지 않고 표시 방식만 교정한다.

[4. 배경·자료·그래프·불꽃]
- 뒤 영상은 계속 흐르게 한다. 글자와 전체 부모의 opacity를 함께 줄이지 말고 검정 반투명 배경 레이어와 글자 레이어를 분리한다. 흰 글씨에는 검정 반투명 배경, 검정 글씨에는 흰 배경이라는 후속 명세를 유지한다.
🌸기사·댓글의 가독성용 검정 배경은 불투명도40%를 시작값으로 하고35%/45%/55% 비교 시안을 만든다. 전체 영상을 상시 어둡게 하지 않고 해당 자료 장면에서만 필요한 범위에 적용한다. 이는 원본 캡처의 alpha를 측정한 확정값이 아니라 가독성 비교용 제안이다. 40% 불투명도는 뒤 영상 기여60%이고,55% 불투명도는45%다. 영상→영상용 색보정→검정dim→카드·형광→글자 순서로 합성한다.
- 대본/장면표의 통계·비교·증감·비율을 찾아 기존 그래프 후보 목록을 만든다. 실제 수치·기간·단위·출처를 연결한다. 후보마다 적용/미적용과 이유를 기록한다. 자료 부족을 숨기거나 그래프 수를 채우려고 숫자를 만들지 않는다.
- 기존 그래프의 막대/선/제목/큰 숫자/출처 디자인을 재사용한다. GitHub 시안에서 확인된 흰 선을 실제 로컬 시안과 대조해 맞추고, VS 빨강을 그래프 전역색으로 잘못 상속하지 않는다.
- 기존 효과 자산6장을 실제로 열어 투명도·파일상태·쓰임을 확인한다. 세로 불기둥=VS 분할선/옆, NO=부정/거절, 만화 테두리=놀람/감탄 가장자리, 아래 불벽=화남/샤우팅/좋다, 아우라=들어오는 사람 뒤, 번개=충격 보조. 사람 옆에 스티커처럼 붙이는 것으로 아우라를 대체하지 않는다.
🌸인물 마스크 뒤에 아우라를 합성하고 얼굴·자막을 가리지 않는지 검수한다. 사용처가 없으면 억지로6개를 모두 사용하지 않고 미사용 이유를 적는다.

[5. 초반 재미와 후반 연속성]
🌸예능감은 실제 발언→실제 반응→짧은 평가→근거 화면의 연결로 만든다. 다른 맥락의 놀란 표정을 해당 발언의 반응처럼 붙이지 않는다. 웃길 구간은 지정 평가/번개/라벨을, 근거를 보여줄 구간은 기사/댓글/그래프를 선택한다.
🌸초반0~12초는 컷0.8~1.8초, 필요한 강세 지점만115~122% 줌을0.18~0.28초에 적용하는 시작값으로 비교한다. 첫 질문이나 결과의 일부를 즉시 보여주고 설명을 연결한다. 회전·더치앵글·큰 효과를 모든 컷에 넣지 않는다.
🌸12~45초는 컷2~3.5초, 본문은2.5~4초를 시작값으로 한다. 반응 클로즈업은110~118%·0.18~0.3초부터 비교한다. 의미 있는 강조/카드/반응 이벤트6~10회/분, 큰 효과3~5회/분은 샘플 비교용 범위이지 의무 할당량이 아니다. 일상적인 컷 변경은 이 이벤트 수에 중복 집계하지 않는다.
🌸읽어야 하는 기사·그래프는5~8초 정도 유지하되 뒤 영상은4초 이하로 바꿀 수 있다. 자료 오버레이 유지시간과 배경 컷 길이를 구분하고, 실제 글자량에 맞춰 읽는 시간을 확보한다.
- 컷4초 이하라는 기존 조건은 유지한다. 이미 만들어진 대본·TTS 길이를 맞추려고 음성을 자르거나 다시 생성하지 않는다. 컷이 바뀐다는 이유만으로 매번 화면을 정지하지 않는다.
🌸후반은3~4초 단위의 자연스러운 컷을 우선하고 원본 기본속도1x, 동작 연결, 절제된 줌으로 안정시킨다. 일반 후반 컷에는 강제 프리즈·반복 프레임·불필요한 스피드램프를 넣지 않는다. 의도한 반전 효과만 별도 이벤트로 처리한다.
🌸필요한 디졸브는30fps 기준6~9프레임, 즉0.2~0.3초부터 비교한다. 실제 프로젝트FPS에 맞는 같은 시간 길이로 환산하며 모든 컷에 강제하지 않는다. 동작이 맞는 직접 컷이 더 자연스러우면 그것을 사용한다.
- 먼저 실제 소스·프로젝트·출력의 주FPS, time_base, PTS 연속성, 반복/누락 프레임, 컷 연결부를 확인한다. 무조건30 또는60fps CFR로 바꾸지 않는다. VFR/CFR 변환이 필요한지 증거를 보고 판단한다.
- xfade/디졸브가 클립 시간을 겹치므로 누적 겹침을 타임라인 계산에 반영한다. 음성·자막은 원래 절대 타임코드에 맞추고 후반으로 갈수록 TTS가 밀리지 않게 한다. 단순히 각 클립 길이를 더하여 전체 길이를 계산하지 않는다.
- 원음 전환·TTS 접합부도 듣고 확인한다. 영상 전환만 바꿨는데 소리가 잘리거나 반복되면 실패다.
💰🌸허가받은 자료는 원본 속도·대화 맥락을 보존하는 방향으로 편집한다. 좌우반전·크롭·배속을 권리 회피 목적으로 자동 강제하지 않는다. 허가 범위와 플랫폼 수익화 평가는 별개이며, 이런 변형만으로 안전이 보장된다고 보고하지 않는다.

[6. 검수와 결과]
- 먼저30초 샘플에서 문제 색/서체, 기사 연두·연노랑, 댓글 구분, 그래프, 기본/디자인 자막 교대, 자연스러운 전환을 확인한다. 원문이 요구한30초 샘플과 대표1편 검수는 둘 다 수행한다.
- 대표1편을 전체 렌더하고 마지막60초를 별도로 집중 확인한다. 기존 대본·TTS 해시 동일, 영상/음성 동기화, 프레임 정지·겹침·빈 화면, 자막 충돌·줄바꿈, 자료출처, 실제 사용 폰트·색을 검사한다.
- PNG 시안이 맞는 것으로 끝내지 말고 실제 인코딩MP4에서 같은 시점의 프레임을 뽑아 비교한다. 최종색이 달라지면 합성·색공간 변환·압축을 나누어 조사한다. 안티앨리어싱 경계 픽셀을 글자 원색이라고 측정하지 않는다.
🌸픽셀 검수는 오버레이 내부색과 최종 합성프레임을 별도 기록하고, 소스색/이미지실측/최종MP4측정을 구분한다. 비디오 압축 뒤 모든 픽셀이 HEX와 완전히 동일하다고 보증하지 않는다.
- 결과는 “직접 확인 / Claude 보고 / 추정 / 미구현”으로 분리한다. 실제 변경 파일, 원인, 변경 전후 프레임, 폰트 준비 상태, 그래프 후보·누락 이유, 대본/TTS 보존, 30초/대표1편/🌸후반60초 PASS·FAIL, 결과 경로를 제공한다. 실패한 항목을 성공으로 묶지 않는다.
- 수정 가능한 부분을 고친 뒤에도 남는 실패만 구체적으로 보고한다. 이미 정해진 색·기존 지시의 승인을 다시 묻고 작업을 멈추지 않는다. 새 제안은 모두🌸, 권리 관련 제안은💰🌸로 구분한다. 대표 검수 전50편 일괄 렌더는 실행하지 않는다.

C. 검수 후 — 기존 에피소드 배치 적용
30초 샘플·대표 1편·마지막 60초의 실제 검수를 통과한 뒤

[C · 샘플 통과 후 / 기존 에피소드 배치 적용]

B의30초 샘플·대표1편 전체·마지막60초 검수가 실제로 통과한 뒤 기존 에피소드에 동일한 교정을 확대한다. 지금까지 만든 대본·TTS·원본 클립은 그대로 사용한다. 새 편집기·새 대본·새 목소리를 만드는 작업이 아니다.

1. 시작 조건과 대상 목록
- 먼저 실제 검수 보고와 프레임을 확인한다. “시안에서 잘 보였다”만으로 최종MP4 검수를 통과했다고 보지 않는다. 미해결 오류가 있으면 해당 오류를 고치고 대표 검수를 통과시킨 뒤 배치를 시작한다.
- 기존50편의 실제 ID·장면표·대본·TTS·입출력 경로를 읽고 대상 목록을 확정한다. 파일명 순서만 보고 누락된 편을 새로 생성하거나 이미 완료된 다른 편을 덮지 않는다. 현재 교정본과 원본을 구별할 수 있는 출력 경로를 사용한다.
- 현재 최신 사용자 요청과 검수 통과한 스타일 버전을 고정한다. 오래된 범용 팔레트·폰트·편당1색·11종 강제혼합 규칙이 다시 들어오지 않게 한다. 다음 세션은 원문과 적용 명세를 함께 읽는다.
- 사용자 지정색과 참고 캡처 대표색을 다시 묻지 않는다. #C7F001/#F2F586는 이미지실측 대표값, #D9FF65 등 기존코드는 사용자 제공값이라는 출처 구분을 유지한다.

2. 에피소드별 실제 문맥 적용
- 언론/댓글/통계/비교/일반자막/한마디평가/충격/감탄/반전의 의미 유형을 장면표에서 확인한다. 같은 예시문구·가짜 댓글·같은 숫자를 모든 편에 재사용하지 않는다.
- 기사에 기사형, 댓글에 댓글형을 적용한다. 댓글은 실제 원문·번역·좋아요·캐릭터 카드 구조를 유지한다. 기사형 형광띠를 댓글 전체의 공통양식으로 바꾸지 않는다.
- 기본 자막과 디자인 자막은 배타적으로 표시한다. 한마디평가의 작은 머리말+큰 본문은 유지하며 별도 기본 자막을 중복 표시하지 않는다.
- 통계 후보마다 자료/단위/기간/출처와 적용/미적용 이유를 기록한다. 그래프 수를 억지로 맞추지 않는다. 필요한 그래프가 장면표에 있는데 렌더에서 빠진 경우를 누락으로 잡는다.
- 실제 반응이 있는 구간에 지정 자막·효과를 적용한다. 같은 유형을 연속 사용하지 말라는 Claude 요약을 무조건 따르느라 문맥을 깨뜨리지 않는다.
- 자산6장은 검증된 파일을 사용하고 용도를 유지한다. 인물 뒤 아우라와 옆 장식은 구별한다. 사용되지 않은 자산은 실패가 아니라 문맥상 미사용으로 기록할 수 있다.
- 기존 하단 배치·상단 임의 제목 금지·영상이 보이는 배경 보호 조건을 유지한다. 해외 원문 글자를 일괄 블러하지 않고 필요한 영역만 처리한다.

3. 영상·음성 연속성
- 대본·TTS 파일 바이트를 바꾸지 않는다. 입력과 작업 후 해시가 일치하는지 확인한다. 비율을 맞추려고 내레이션을 늘리거나 줄이지 않는다.
- 컷4초 이하를 유지한다. 🌸후반3~4초 중심·기본1x·의미 없는 프리즈 금지·동작 연결은 대표 샘플에서 통과한 제안값을 이어 적용한다.
- 소스·프로젝트의 실제FPS를 유지하는 방향으로 처리한다. 모든 파일을30/60fps로 일괄 강제하지 않는다. PTS·시간축의 연속성을 검사한다.
- 디졸브/xfade의 겹침 시간을 반영하고 원래 TTS·자막의 절대 타임코드를 보존한다. 후반으로 갈수록 음성·화면이 밀리면 그 편을 완료로 처리하지 않는다.
- 원본 소리의 문장이 잘리거나 같은 말이 반복되는 접합부가 없는지 확인한다. 프로그램이 정상 종료됐다는 것만으로 시청 품질 PASS를 부여하지 않는다.
💰🌸허가받은 원본의 맥락을 보존하고 권리회피용 자동 좌우반전·배속을 강제하지 않는다. 수익화 승인이나 저작권 안전을 편집효과만으로 보증하지 않는다.

4. 🌸배치 운영 제안
🌸작은 묶음으로 실행하며 완료·실패·대기를 에피소드별로 기록한다. 일부 실패가 다른 편의 원본이나 완료물을 덮지 않게 한다.
🌸이미 동일 규칙 버전으로 통과한 편은 재렌더하지 않고, 입력·스타일·렌더러 변경으로 영향을 받는 편만 갱신한다. 재실행 시 완료 항목을 식별할 수 있게 한다.
🌸각 편에 사용한 스타일버전·폰트확인·색출처·그래프후보·자막배타성·주FPS·영상길이·출력경로·입력/출력 해시를 기존 마스터표와 연결한다.
🌸최종MP4의 해당 장면 프레임과 후반 전환 표본을 확인한다. 같은 PNG 시안만 반복 검사하지 않는다. 문제 유형이 발견되면 그 유형이 있는 나머지 편으로 검증 범위를 넓힌다.

5. 완료 보고
- 전체 대상수, 완료, 실패, 대기, 변경 없는 편을 구분하고 각 실패에는 에피소드ID·타임코드·재현근거·다음수정사항을 적는다.
