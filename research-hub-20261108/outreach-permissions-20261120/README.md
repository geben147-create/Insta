## 절대 지킬 규칙
1. 동일한 채널이나 수신 주소에 새 1차 허락 요청을 중복 발송하지 않습니다.
2. `REFUSED`는 영상 사용 금지 및 재접촉 금지입니다.
3. `NEEDS_INFO`는 정확한 원본 URL·사용 구간·제작 방향을 제시해 기존 이메일 스레드로 답장합니다.
4. `POSITIVE_NEEDS_SCOPE`는 긍정 의사일 뿐입니다. 원본 링크와 상업적 이용 등 실제 사용 범위 확인 전까지 영상 사용 불가로 유지합니다.
5. `DELIVERY_FAILED`는 해당 주소를 재시도하지 않습니다. 공식 방송사 다른 창구는 따로 검증해야 합니다.
6. 수신 여부, 사람이 읽었는지, 실제 법적 이용 허락 여부를 Gmail 발송 성공과 혼동하지 않습니다.
7. 공개 GitHub에는 상대방 답장 원문, 실제 이메일 주소, Gmail 메시지 ID를 게시하지 않습니다. 원본 증거는 Gmail에 남겨 둡니다.

## 중복 발송 방지
- `contacts.json`의 `contact_sha256`은 수신자 이메일(소문자·양쪽 공백 제거)의 SHA-256입니다.
- 새 후보의 이메일을 대시보드의 **중복 검사**에 넣으면 브라우저 안에서만 SHA-256을 계산합니다.
- 동일 이메일이 없어도 다른 주소로 같은 채널에 이미 발송했을 수 있으므로 **채널·영상 링크**까지 대조합니다.
- 새 발송 전에 Gmail에서 `in:sent to:<상대 업무용 이메일>`을 확인합니다.
- 모든 발송 기록은 `skip_new_outreach=true`입니다. 이는 후속 대화 금지가 아니라 **새 첫 연락 메일 중복 발송 금지**입니다.
- `may_use_video=false`는 허락 범위가 실제로 확정되기 전까지 기본값입니다.

## 추가 개선
수정 이력은 GitHub에 남기고, 비공개 원문은 Gmail에 남기는 **공개 대장 + 사적 증거 분리** 방식으로 운영합니다.

## Hermes / n8n / Claude에서 발송 전 검사

```bash
python3 check_before_send.py --email 'candidate@example.com' --channel-url 'https://www.youtube.com/@channel'
```

- 종료코드 `3`: 이 대장에서 중복 감지. **발송 금지**.
- 종료코드 `4`: 명단을 읽지 못함. **발송 금지**.
- 종료코드 `0`: 이 명단에 없음. **Gmail 보낸편지함·다른 채널명·다른 주소를 추가 대조 후** 승인할 것.
- 공개 GitHub 파일에 이메일이 저장되는 것은 아닙니다. 검사는 실행 PC에서 해시로 수행합니다.
- 이 도구를 실제 발송 워크플로의 선행 단계에 연결해야 자동으로 발송을 차단합니다. 현재 기존 발송 자동화에 이미 연결된 것은 아닙니다.
