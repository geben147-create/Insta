## 2. 유튜브 존재 확인 (유튜브존재확인.tsv)
- 표 시트의 '[1] 전체 상위 30' + '[3] 최신 급등'·'[4] 역대 바이럴'에서 중복 제외해 채움. 중복 제외 후 고유 항목이 **39개**라 40개를 못 채움.
- 방법: 한국어 번역 제목 + "중국인"으로 YouTube 검색(KR, 상위 3개) 후 직접 비교.
- 결과: 39개 모두 **없음** (상위 결과는 숏드라마, 뉴스 등 무관한 영상).
- 한계: 원문 중국어 제목과 크리에이터명으로는 검색 못 함(CSV에 원문 없음). 그래서 '없음'은 "번역 제목으로는 찾을 수 없음"이라는 뜻이고, 완전히 없다고 단정할 수는 없음.

## 3. 이전 실행에서 TikTok과 Bilibili 결과가 적었던 이유 (관찰 기준)
- **Bilibili**: 옛 검색 API(/x/web-interface/search/type)가 **412**(안티크롤링 차단)로 막힘. 새 WBI 검색 API는 200이지만 결과 대신 `v_voucher`(위험 제어 토큰)만 돌려줌 → 사실상 인증 요구. nav API로 보면 로그인 상태는 맞음(isLogin=true). 하지만 기본 아바타라 신규/저신뢰 계정으로 보임.
  - 개선책: (1) API 대신 로그인된 브라우저 탭에서 search.bilibili.com을 사람처럼 천천히 넘기기 (2) WBI 서명(w_rid/wts)과 buvid3 쿠키를 갖춘 요청 쓰기 (3) 요청 간격 늘리기 (4) 계정 신뢰도 올리기(휴대폰 인증 등. 사용자 판단 필요).
- **TikTok**: 검색 페이지 HTML(약 388KB)은 오지만 결과는 JS + 서명 API(X-Bogus/msToken)로 불러옴 → fetch로는 결과 0. 비로그인 웹 검색은 몇 개만 보여주고 로그인 모달이나 퍼즐 CAPTCHA를 띄우는 경우가 잦음. 지역(KR IP) 추천 편향도 있음.
  - 개선책: 로그인된 실제 탭에서 검색 후 스크롤해서 DOM 읽기, 해시태그/크리에이터 페이지 위주로 수집, 국가별 언어 키워드 쓰기, CAPTCHA가 뜨면 사용자가 직접 풀기.
- 공통: 해외 IP나 클라우드 IP는 중국 플랫폼에서 위험 등급이 높게 잡힘. 그리고 한 세션에서 연속으로 요청하면 차단이 빨리 옴.
